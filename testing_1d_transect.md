# Testing the 1D Transect Adaptation

This document explains how to test the end-to-end 1D adaptation of the `satvision-pix4d-base` (SatMAE ViT) model. The adaptation allows the model to consume `512x1` transect/profile data rather than `512x512` spatial tiles.

## Prerequisites

Before testing, ensure you have the proper environment activated. It must contain the required dependencies:
* `pytorch`
* `timm`
* `yacs`
* `lightning`
* `huggingface_hub` (if downloading weights)

For example:
```bash
module load anaconda
source activate satvision-pix4d
```
*(Adjust the above according to your specific cluster/node setup).*

---

## 1. Local / Interactive Smoke Test

You can run the script interactively on a head node or interactive node just to verify that the environment loads, the architecture builds, and the pretrained 2D weights reshape correctly without shape mismatches.

Run the finetuning script directly from the root of the repository:
```bash
python scripts/finetune_transect.py
```

### What to watch for in the console output:
1. **Model Building & Shape Overrides:** You should see the configuration printout acknowledging `IMG_SIZE: (512, 1)` and `PATCH_SIZE: (16, 1)`.
2. **Weight Reshaping:** If loading a 2D pre-trained checkpoint, look for a log indicating successful shape-collapsing, such as:
   `Reshaping patch_embed.proj.weight: [1024, 16, 16, 16] → [1024, 16, 16, 1] (averaging width dim)`
3. **Training Loop:** It will attempt to start the PyTorch Lightning trainer (Epoch 0/1). Once you see the validation/training progress bar start, you can safely cancel (`Ctrl+C`) if you do not wish to train on the interactive node.

---

## 2. Full Slurm Job Submission

To run a full finetuning job on the compute cluster (GPU node):

1. **Verify the Submission Script**
   Open `scripts/submit_finetune_transect.sh` and ensure the following match your environment:
   * Slurm `#SBATCH` directives (GPU type, node count, queue).
   * Environment activation commands (e.g., `module load`, `source activate`).
   * `DATA_DIR` points to the correct directory containing your `.npz` transect data.
   * `PRETRAINED_WEIGHTS` points to the `mp_rank_*.pt` or `.ckpt` file you intend to use.

2. **Submit the Job**
   ```bash
   sbatch scripts/submit_finetune_transect.sh
   ```

3. **Monitor Progress**
   The script creates a `logs/` directory automatically. You can monitor the job in real-time by tailing the log file:
   ```bash
   tail -f logs/transect_finetune_<JOB_ID>.log
   ```

### Notes on Checkpointing
* **First Run:** The script will automatically collapse the width dimension of your 2D pre-trained checkpoint into a 1D format.
* **Resuming:** If you resume training from a `.ckpt` file generated by *this* finetuning script, the script will automatically recognize that the weights are already in the 1D format and will load them directly without attempting to average the width dimension again.
